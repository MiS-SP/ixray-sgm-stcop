# Улучшения оружия под текущий баланс

Актуализация: 2026-09-06. Основа — рабочие конфигурации SGM и STCOP, включая пользовательские изменения. Реализация ориентирована на новую игру: старые установленные upgrade ID не переносятся в новые деревья.

## Что изменено

Для 65 самостоятельных моделей STCOP созданы собственные деревья: 1090 узлов вместе с заменой основных компонентов. Варианты с прицелами наследуют дерево своего оружия. Определения находятся в `configs/weapons/stcop/upgrades/families/`; список `stcop_upgrades.ltx` подключает их в глобальный INI и в `item_upgrades.ltx`.

Топология новых веток взята из оригинальных деревьев CoP: последовательные ступени, альтернативные узлы в одной группе и общие последующие ступени. «Замена основных компонентов» добавлена отдельной группой SGM с исходными требованиями к рангу. Не переносятся узлы, которые меняют калибр, режимы огня или разблокируют чужой обвес. У исходных SGM-деревьев сохранены ID и имеющаяся структура.

Дробовикам назначены шаблоны СПАС-12 или Winchester 1300, пистолетам-пулемётам — MP5, самозарядным снайперским винтовкам — СВД. У винтовок и пулемётов сохранены подходящие исходные доноры. Настройки базового оружия, боеприпасов и обвесов этим изменением не переписываются.

## Пересчёт

Движок прибавляет числовые поля большинства улучшений, а `hit_power` заменяет целиком. Запись `+20` — прибавка двадцати единиц, а не двадцати процентов. Процентный синтаксис в этих параметрах не используется.

- Для прибавок: `новая прибавка = исходная прибавка × новая база / исходная база`.
- Для замены урона: сохраняется отношение улучшенного урона к исходному, отдельно для компонентов вектора сложности.
- Для существующего оружия исходная база взята из HEAD перед текущими пользовательскими правками; для нового дерева — из соответствующего оружия-донора. Характеристики рабочего дерева являются новой базой.
- Вместимость магазина округляется до целых патронов. Цена масштабируется относительно стоимости оружия-донора и округляется до 50 RU, с минимумом 100 RU до скидок и надбавки SGM.
- Если допустимое сочетание улучшений уводило износ, вероятность осечки, разброс, отдачу, инерцию или массу ниже нуля, отрицательные прибавки этой характеристики пропорционально ограничены: остаётся не менее 10% исходного значения для проверяемого дерева. При общей секции учитываются уникальные варианты с меньшей базой.
- Число `value` у поддерживаемых процентных свойств рассчитывается из фактического бонуса и для интерфейса округляется вниз по модулю до шага 5%; ненулевой бонус меньше 5% показывается как 5%, чтобы платное улучшение не отображалось как 0%. Знак эффекта сохраняется (`-23.33` становится `-20`, `+14.6` становится `+10`). Это поле не заменяет игровой параметр. Масса, вместимость магазина и другие непропорциональные величины не округляются по этому правилу. Для комплексной замены компонентов сохранено общее описание.

Это баланс конфигураций, а не автоматический runtime-пересчёт: после дальнейшего изменения базы нужно пересмотреть затронутые прибавки и проверить сочетания. Не копировать весь файл донора. Собственные секции наследуют общие подписи, иконки и функции; напрямую задаются ссылки дерева, требования и необходимые числовые отличия.

## Механики без копий таблиц

В секции нового оружия `sgm_upgrade_mechanic` указывает исходное оружие, чьим доступом к механикам оно пользуется. В новой секции эффекта `sgm_upgrade_requirements` указывает исходный эффект, чьи требования к инструментам и рангу применяются.

Общий SGM helper `sgm_upgrade_support.create_mechanic_reader()` подключается существующим стартовым адаптером IXR Framework через штатный `inventory_upgrades.override_param_ini`. Он читает действующие условия из исходной таблицы, а не копирует их. Явная запись для нового ID имеет приоритет, включая `false`. Для вариантов с прицелами без явного alias используется `parent_section`. Стоимость, списание денег, скидки и выполнение улучшений остаются у штатных функций и SGM callbacks.

Это статические LTX-ссылки, а не обмен runtime-сервисами между аддонами. Базовый SGM не содержит ID оружия STCOP и работает при его отключении.

## Проверка

Разовыми проверками проверены оба INI-контекста, доступность родителей и ссылок, отсутствие пересечений координат внутри новых деревьев, координаты в обычной и широкоформатной UI-схемах, русские и английские подписи новых деревьев и минимальные значения при сочетании бонусов. Lua проверяется через LuaJIT; reader проверяется с SGM отдельно и с STCOP, включая приоритет явного запрета, исходные требования и повторное создание.

Игровая проверка выполняется человеком после полного перезапуска, на новой игре: открыть у механика по одному представителю каждого класса и вариант с прицелом, проверить блокировки ступеней и альтернатив, требования инструментов/ранга, списание цены и замену компонентов. Сохранить и загрузить оружие с установленными новыми улучшениями. Это необходимая проверка поведения в игре; статические проверки её не заменяют.
